# Action Log — Execution Logging Instrumentation + Recursive E2E Fixes

**Date:** 2026-07-06
**Scope:** Implement forensic execution logging (8 gaps from prior audit), then test with a complex multi-phase prompt, analyze the resulting log from a neutral POV, and recursively fix the defects found.

---

## Phase 1 — Implement execution logging (code changes)

### 1. `src/utils/api_guard_middleware.ts`
- **Why:** Gap #2 (retry/error fidelity). Retry events were invisible.
- **What:** Added exported `RetryEvent` interface. `executeWithRetry` now accepts a `retryAccumulator: RetryEvent[]` parameter and pushes structured events (attempt, error_type, error_message, error_stack, http_status, timeout_duration_ms, api_key_id_from/to, cooldown_ms, duration_ms, provider) before each key rotation. Added `getActiveKeyId(provider)` so key IDs are exposed.

### 2. `src/utils/reporter.ts`
- **Why:** Gap #8 (timing coverage gaps). Reporter DB/file I/O was unmeasured.
- **What:** `recordDecision`, `recordObservation`, `updateTaskStateFile`, `writeExecutiveSummary`, `writeTechnicalReport`, `writeReflection` now return `{ ..., duration_ms }` and `updateTaskStateFile` additionally returns per-phase `load_ms / append_ms / save_ms`.

### 3. `src/utils/tool_dispatcher.ts`
- **Why:** Gap #4 (validation/schema-parsing phase invisible).
- **What:** `ToolResult` extended with `validation_error?` and `schema_used?`. Each Zod parse failure now returns ERROR with those fields populated. Added `schemaMap` name lookup so the schema name is captured.

### 4. `src/utils/interpreter.ts`
- **Why:** Gap #4 (propagate validation metadata to observations).
- **What:** `ObservationResult` gained `validation_error?` / `schema_used?`, populated from `ToolResult`.

### 5. `src/utils/sys_inspect.ts`
- **Why:** Gap #3 supporting detail (skeleton cache telemetry).
- **What:** `SkeletonResult` carries `cache_hit`; `SysInspect` exposes `getCacheStats()`.

### 6. `src/utils/execution_logger.ts` (new)
- **Why:** Single source of truth for the forensic log (Gaps #1, #3, #5, #7, #8).
- **What:** `MicroStep` interface (every field the audit asked for). `buildExecutionLog()` assembles mission metadata, micro-steps, embedded reflection contents, artifact SHA-256 hashes, environment fingerprint, and a `validation` block with warnings. `writeExecutionLog()` persists `reports/missions/execution_log_<missionId>.json`.

### 7. `src/utils/agent_loop.ts`
- **Why:** Instrument every phase of `runTaskLoop`.
- **What:** `executeMission` now accumulates `microSteps` and writes the log at the end. Each loop iteration captures LLM request/response (raw text + char counts), decision parsing, validation phase, tool execution, observation, all DB/file timings, retry events, skeleton injection metadata, `reflection_type` (`tool_action`/`null_action_continue`/`completion`) and `completion_signal`. `buildStateSummary` truncated to avoid token bloat.

## Phase 3 — Neutral analysis of the log (recursive fix trigger)

The log proved the instrumentation works, but exposed 5 defects:

| # | Finding (neutral) | Severity |
|---|---|---|
| A | `database_records.decision_count: 0` / `observation_count: 0` though 5 decisions + observations exist. Real data not counted. | High |
| B | `reflections_content` and `task_states` list **every** mission's artifacts, not just the current one (e.g. reflections 12,16,17,18…23,24 included). Log is polluted. | High |
| C | `llm_request.api_key_id` always `""`. Key ID never captured. | Medium |
| D | `state_summary_before/after` embed full multi-line error stacks → every subsequent LLM prompt grew ~2KB/step (token bloat). | Medium |
| E | `reformulated_mission_id_matches_executed: false` — tool-chain `missionId` (params) differs from executed mission id. Pre-existing reformulator design gap, not introduced here. | Low (noted) |

### Root causes
- A: `buildExecutionLog` hardcoded `decision_count: 0` / `observation_count: 0`.
- B: globs read the whole `reflection/` and `tasks/` dirs without mission scoping.
- C: `api_key_id: ""` literal in `agent_loop.ts`.
- D: `buildStateSummary` appended raw `observation.error` (full Zod output / ffmpeg trace).

## Phase 4 — Recursive fixes (applied)

### `src/utils/database_helper.ts`
- Added `countDecisionsByMission(missionId)` and `countObservationsByMission(missionId)` (JOIN decisions→observations).

### `src/utils/execution_logger.ts`
- Reflections now only included if their content contains the current `missionId` **or** `Task: <id>`; task-state files only if they contain the `missionId`.
- `database_records.decision_count/observation_count` now use the new counters.

### `src/utils/agent_loop.ts`
- `api_key_id: this.apiGuard.getActiveKeyId("zhipu")` instead of `""`.
- `buildStateSummary` truncates thought and error to 200 chars each.

### `src/utils/prompt_reformulator.ts`
- No change this round (defect E is a pre-existing design choice: tool-chain steps carry their own `missionId` from `extractMissionId()`, which differs per-call). Flagged for a later pass — would require threading the executed missionId into `generateToolChain`.
